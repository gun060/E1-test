# Open House · Popular Vote (Node.js + PostgreSQL + Google Sign-In)

ทุกคน (ผู้โหวต ผู้ขาย คุณครู) เข้าสู่ระบบด้วยบัญชี Google
- **ผู้โหวต**: เข้าสู่ระบบแล้วโหวตได้ 1 บัญชี 1 ครั้ง (หน้าแรก `/`)
- **ผู้ขาย/คุณครู**: เข้าสู่ระบบที่ `/staff.html` แล้วส่งคำขอสมัคร คุณครูกดอนุมัติ

## 1) โครงสร้างไฟล์

```
popular-vote-server/
├── server.js
├── package.json
├── .gitignore
├── README.md
└── public/
    ├── index.html     ← หน้าโหวต
    └── staff.html     ← หน้าผู้ขาย/คุณครู
```
ไม่ต้องอัปโหลดโฟลเดอร์ `node_modules` และโฟลเดอร์ `popular-vote` (เวอร์ชัน Google Sheets เดิม)

## 2) ลำดับการติดตั้ง

### A. เตรียมบัญชี
สมัคร GitHub, Render และมีบัญชี Google (ใช้เข้า Google Cloud)

### B. อัปโหลดโค้ดขึ้น GitHub
สร้าง repository Private แล้วอัปโหลดไฟล์ตามโครงสร้างข้างบน (`server.js` และ `package.json` อยู่ราก, `index.html` กับ `staff.html` อยู่ในโฟลเดอร์ `public`)

### C. สร้างฐานข้อมูลบน Render
New > PostgreSQL (Free) แล้วคัดลอก **Internal Database URL**
Postgres ฟรีมีอายุจำกัด (ปัจจุบัน 30 วัน ตรวจเงื่อนไขในหน้าสร้างอีกครั้ง) ควรสร้างก่อนงานไม่เกินสองสามวัน

### D. สร้าง Web Service บน Render
New > Web Service > เลือก repo ตั้งค่า Build Command `npm install`, Start Command `npm start`, Instance Type Free
Environment Variables:

| ชื่อ | ค่า |
|---|---|
| `DATABASE_URL` | Internal Database URL จากขั้น C |
| `TEACHER_EMAILS` | อีเมล Google ของคุณครูคนแรก คั่นหลายคนด้วยจุลภาค เช่น `teacher1@gmail.com,teacher2@gmail.com` (ได้สิทธิ์ครูอัตโนมัติเมื่อเข้าสู่ระบบ) |
| `GOOGLE_CLIENT_ID` | ยังไม่ต้องใส่ ได้มาในขั้น F |
| `FLAG_IP_VOTES` | (ไม่บังคับ) จำนวนโหวตจาก IP เดียวกันที่จะถูกติดป้าย "ตรวจสอบ" ค่าเริ่มต้น 8 |

### E. ตรวจว่าเซิร์ฟเวอร์ทำงาน
เปิด `https://ชื่อบริการ.onrender.com/healthz` ต้องขึ้น `ok` และจดโดเมนนี้ไว้ใช้ในขั้นถัดไป

### F. สร้าง Google Client ID (ฟรี)
เมนูและชื่อปุ่มของ Google Cloud อาจเปลี่ยนไปบ้าง ให้ยึดตามความหมาย
1. เข้า console.cloud.google.com สร้างโปรเจกต์ใหม่
2. ไปที่ APIs & Services > OAuth consent screen (หรือ Google Auth Platform) ตั้งค่าแอป: User type = **External** ใส่ชื่อแอปและอีเมลติดต่อ
3. **Publish app / เปลี่ยนสถานะเป็น In production** ถ้าค้างในโหมด Testing จะมีเฉพาะผู้ใช้ทดสอบที่คุณเพิ่มไว้เท่านั้นที่เข้าสู่ระบบได้ คนอื่นจะโหวตไม่ได้ (การขอแค่ข้อมูลพื้นฐาน เช่น อีเมลและชื่อ ปกติไม่ต้องผ่านการตรวจสอบเพิ่ม)
4. ไปที่ Credentials > Create credentials > **OAuth client ID** > Application type = **Web application**
5. ที่ **Authorized JavaScript origins** ใส่โดเมนเว็บของคุณ เช่น `https://ชื่อบริการ.onrender.com` (ไม่ต้องมี `/` ท้าย และไม่ต้องใส่ Redirect URI)
6. คัดลอก **Client ID** (ลงท้ายด้วย `.apps.googleusercontent.com`)

### G. ใส่ Client ID
ใน Render > Web Service > Environment ใส่ `GOOGLE_CLIENT_ID` แล้วบันทึก ระบบจะรีสตาร์ตเอง

### H. ทดสอบ
1. เปิดหน้าแรก ต้องเห็นปุ่ม "Sign in with Google" ด้านล่าง ลองเข้าสู่ระบบ เลือกร้านและโหวต แล้วลองโหวตอีกครั้ง ต้องถูกปฏิเสธ
2. เปิด `/staff.html` ด้วยอีเมลที่อยู่ใน `TEACHER_EMAILS` ต้องเห็นหน้าคุณครู ผลโหวตเพิ่มเองใน 5 วินาที
3. ใช้อีกบัญชี Google เข้า `/staff.html` ส่งคำขอเป็นผู้ขาย แล้วกลับไปหน้าครู กดอนุมัติ ผู้ขายกด "ตรวจสอบสถานะอีกครั้ง" ต้องเห็นเฉพาะคะแนนร้านตัวเอง ไม่มีอันดับ
4. ลองในโหมดไม่ระบุตัวตนหรือเครื่องอื่นด้วย เพื่อดูว่าเข้าสู่ระบบได้ปกติ

### I. ล้างข้อมูลทดสอบ (ทำก่อนวันงาน)
โหวตที่ใช้ทดสอบจะติดไปในผลจริง และบัญชีที่โหวตไปแล้วจะโหวตซ้ำไม่ได้ เชื่อม psql กับ External Database URL แล้วรัน:
```sql
TRUNCATE ballots, adjustments;
```
บัญชีครูและผู้ขายที่อนุมัติแล้วยังอยู่ตามเดิม

### J. ก่อนงาน
- เปิดเว็บทิ้งไว้อย่างน้อย 15 นาทีก่อนเริ่ม เซิร์ฟเวอร์ฟรีหลับเมื่อไม่มีคนใช้ 15 นาทีและตื่นช้าราว 1 นาที
- ให้ผู้ขายแต่ละคนเข้า `/staff.html` สมัครล่วงหน้า แล้วครูอนุมัติให้เรียบร้อย
- แจ้งผู้เข้าร่วมว่าระบบเก็บอีเมลและ IP เพื่อกันโหวตซ้ำ (ข้อมูลส่วนบุคคล) และจะลบหลังจบงาน
- ป้ายประกาศหน้างานควรแนะนำให้เปิดลิงก์ด้วย Chrome หรือ Safari เพราะเบราว์เซอร์ในแอปแชตบางตัว (เช่น LINE) อาจเข้าสู่ระบบ Google ไม่ได้

### K. วันงานและหลังงาน
- ครูเปิด `/staff.html` ตลอดงาน ดูผล ตรวจรายการโหวตที่ติดป้าย "ตรวจสอบ" และกดยกเลิกโหวตที่ไม่ชอบมาพากล
- ปิดโหวตเมื่อหมดเวลา แล้วกดส่งออก CSV
- หลังงานลบ Web Service และฐานข้อมูล เพื่อลบอีเมลและ IP ที่เก็บไว้

## 3) การกันปั๊มโหวต (และข้อจำกัด)
- 1 บัญชี Google = 1 โหวต ตรวจที่เซิร์ฟเวอร์ และต้องเป็นอีเมลที่ Google ยืนยันแล้ว
- ผู้ขายโหวตให้ร้านตัวเองไม่ได้
- จำกัดความถี่ต่อ IP และติดป้าย "ตรวจสอบ" ให้ IP ที่โหวตถี่ผิดปกติ (ไม่บล็อกอัตโนมัติ เพราะ Wi-Fi งานทั้งงานอาจใช้ IP เดียวกัน)
- ครูยกเลิก/คืนโหวตรายรายการได้ และมีคอลัมน์อีเมลให้ตรวจรูปแบบที่ผิดปกติ เช่น อีเมลชื่อคล้ายกันเป็นชุด
- **ข้อจำกัด:** ใครก็สร้างบัญชี Gmail ใหม่ได้หลายบัญชี ระบบจึงกันการปั๊มโหวตด้วยบัญชีใหม่จำนวนมากได้ไม่เด็ดขาด ถ้ากังวลมาก ควรกลับไปใช้บัตร QR ใช้ครั้งเดียวร่วมด้วย หรือจำกัดโดเมนอีเมลโรงเรียนในอนาคต

## 4) แก้ปัญหา
| อาการ | วิธีแก้ |
|---|---|
| ไม่เห็นปุ่ม Sign in with Google | ยังไม่ได้ใส่ `GOOGLE_CLIENT_ID` หรือยังไม่ได้รีสตาร์ต |
| กดปุ่มแล้ว Google แจ้ง origin ไม่ถูกต้อง | โดเมนใน Authorized JavaScript origins ไม่ตรงกับโดเมนที่เปิดอยู่ (ต้องตรงทุกตัวอักษร รวม `https://`) |
| บางคนเข้าสู่ระบบไม่ได้ แจ้งว่าแอปยังไม่ได้เผยแพร่ | แอปยังอยู่โหมด Testing ให้ Publish เป็น In production |
| ผู้ขายสมัครแล้วยังเข้าหน้าผู้ขายไม่ได้ | ต้องให้ครูอนุมัติก่อน แล้วกด "ตรวจสอบสถานะอีกครั้ง" |
| ไม่มีใครเป็นครู | ตรวจอีเมลใน `TEACHER_EMAILS` ว่าตรงกับบัญชีที่ใช้เข้า แล้วเข้าสู่ระบบใหม่ |
| Deploy ไม่ผ่าน / ขึ้น error ฐานข้อมูล | ตรวจ `DATABASE_URL` และดู Logs ใน Render |
